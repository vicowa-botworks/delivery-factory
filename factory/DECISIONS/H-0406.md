## H-0406 · The factory moved out of `parental-lockout` into `vicowa-botworks/delivery-factory` — what carries, what gets left readable, and how the gates hold on a tree without a product?

- Question: `factory/` was extracted from `vicowa-botworks/parental-lockout` into the new private
  repository `vicowa-botworks/delivery-factory` so it can work on any watched repository. The
  carried history is a `git filter-repo` graft: 1093 commits kept, only harness paths kept.
  Three things broke on the far side: dozens of decision-log citations name product files that
  are not in this tree; ~250 `Checkpoint:` fields and ~15 `sha (PR #N)` provenance pairs name
  commits the graft rewrote or dropped; and the root decision log was a header, which its own
  scanner refuses as "what a log that has stopped being written looks like". What is the *truth*
  each of those pointers claims, and which representation of it survives a graft?
- Options: rewrite every affected entry's prose into the new ids -- 112+ rows edited, every
  coordinate in them re-verified, and the rows they *quote* still drift anyway | delete the broken
  pointers -- #429's rule forbids it: the id and the pointer are one claim | leave the log
  byte-identical to the parent's and teach the git rules and the path rule to resolve through the
  extraction itself -- the `filter-repo` commit map shipped beside the log
- Chose: leave the log byte-identical to the parent's and teach the git rules and the path rule to
  resolve through the extraction itself -- the `filter-repo` commit map shipped beside the log
- Why: a decision-log pointer is evidence, and the evidence it offers is about the parent tree at
  the extraction point. Rewriting prose into graft-local ids manufactures new text the scanner
  then re-verifies against a tree that is no longer the one the entry measured — it edits the
  witness to fit the verdict. The map states exactly one checkable fact per commit — existed,
  carried under id X, or dropped into product-only paths — so a fabricated sha, the hole this
  rule was written to plug (H-0021..H-0023), is refused because it appears on *neither* side.
  A revision-qualified `path:line` likewise names the tree to open rather than pretending the
  current tree answers it, which is the scanner's own exemption, not an invention here.
- Checkpoint: 2033ff1
- Effect: `vicowa-botworks/delivery-factory` `main` is the extracted harness. The graft ran at
  `2adea1bab529`, the verified tip of the parent's `main` (local, `origin`, and the GitHub tree
  read back equal); the parent history is *not rewritten* — nothing in `parental-lockout` moves,
  its forward delete commit is a later phase. `scripts/extraction-commit-map` is the `filter-repo`
  old→new map (1878 rows: 1103 carried, 775 with an all-zero new side, meaning the commit touched
  only paths the extraction left in the product) and it ships in this repository because it
  decodes the history beside it; the scanner reads it, not a machine-local `.git` artifact.
  `scripts/check-decisions.py` grows the parent-lineage seam: `parent_lineage(sha)` answers
  carried or dropped, and a token on *neither* side of the map stays the refusal it was — the
  fabricated-checkpoint hole (H-0021..H-0023, and the `cf00b44` drift #433 priced) stays plugged.
  The checkpoint resolver passes through the map; the #433 provenance pair passes the existence
  half through it and declines to re-read a *message* it cannot open, on the recorded receipt:
  that pair was gated against the object itself in the parent repository before the graft.
  A citation's promise is about a tree, so every coordinate this extraction strands takes the
  revision-qualified form `2adea1ba:path:line` — 112 such pins in the harness logs, each one a
  pointer the parent's own gate held true at that revision (verbatim at
  2adea1ba:factory/DECISIONS.md, no backticks there to protect: that row is the receipt).
  Re-qualifying rows changed the backtick texture of the lines that *quote* pointers, which
  re-classified some cites from unanchored debt to anchored; the drifted ones (48 over three
  rounds, each named by the gate) were re-pinned at the coordinates the gate itself reported
  rather than chased by hand. `POINTER_DEBT` is re-measured to 376 on this tree (from the 589
  this constant carried from the product): the fall is what leaving the product corpus behind
  composes, and the rise the pinning caused is included in the 376 — pinned-then-unanchored rows
  are debt, not exempt; #374's refusal of the bare path stands. The root log opens with `D-0001`
  (which log governs what). The selftest's two product-coupled legs (the NEXT.md instruction
  census, and `469-pinned-fetch-retry` parsing `../.github/workflows/ci.yml`) were cut here —
  they test the product, and this tree is not it; the 469 legs report as loud SKIPs, not silence.
  Disclosure of the seam's cost: a checkpoint naming a dropped commit is true of the parent
  lineage and *not revertible here* — `git revert` in this repository cannot reach it; the map's
  row for it is 40 zeros, which is the disclosure, and `git cat-file` in the parent repository
  still opens it. And the provenance message half is no longer re-verified on this side of the
  seam for parent-lineage pairs, only receipted; the scanner's comment says so at the `continue`
  rather than pretending the read happened.
  Disclosed beside it — the first push attempt of this branch *did not happen*: a chained command
  that appended a trailer then pushed was truncated by output limits and never executed; the
  remote read back `isEmpty: true` minutes after the push had been narrated. It is recorded here
  because the read-back rule (#1180) is that a narration is not a receipt, including this
  session's own. A bundle of the full pre-push state lives at
  `~/.local/share/delivery-factory/pre-push-20261125.bundle`.
  False leads caught on the way, recorded because each nearly became a "fix": (a) the three
  README.md:588 rows looked like graft casualties and are partly not — that coordinate was
  parent-side drift the parent gate itself had grandfathered into debt, so the rows are
  revision-pinned on the strength of a receipt, not of an anchor that was held; (b) the
  "all-zero checkpoints" found by grep were a `grep -c` mis-read — the log carries the *original*
  shas verbatim, and the true zero story is the 775 map rows no grep of the log would show;
  (c) an early bulk-rewrite pass zeroed sha-shaped tokens inside *prose quotes* before the pass
  was reverted whole — which is itself the argument for the seam over in-log rewriting.
- Decision: H-0406
