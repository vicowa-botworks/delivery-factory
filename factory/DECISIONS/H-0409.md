## H-0409 · With the poke structurally blind to the harness repository, does the supervisor gain a second queue, a second ask, or a paragraph of prose?

- Question: `AGENTS.md` makes the reviewer request the supervisor's component — "the component
  that does it is the supervisor's poke, not whoever opened the pull request" — and the incident
  behind that rule is four pull requests sitting in `REVIEW_REQUIRED` for three days with an
  empty `/requested_reviewers` list. H-0407 put the harness in its own repository, and
  `factory_request_review` posts to `repos/$FACTORY_OWNER/$FACTORY_NAME`, which the split made
  the TARGET's repository. A pull request opened against the harness — the only place the
  harness's own code is delivered — was therefore invisible to the component the rule says owns
  the ask; measured (#3 half 2): this repository's #1 merged only because a person read it by
  hand. What owes the ask in the harness repository now?
- Options: full queue integration — the pass also triages, ticks and merges the harness
  repository, one supervisor over both queues — but that hands an unattended loop authority to
  ship the code that ships it: its ticks would edit, approve-gate and merge the merger, and
  `allow_squash_merge=false` makes every such merge permanent history | documentation-only, the
  issue's own fallback — name the ask in the body and on the artifact, and write the coverage
  limit into `docs/factory.md` — but that leaves the `AGENTS.md` sentence true on one repository
  and false on the other, which is exactly the combination #3 called worse than an absent
  promise, because the prose still tells every opener someone else asks | asks-only sweep of the
  harness repository each pass, with its own journal words and its own ledger namespace
- Chose: asks-only sweep of the harness repository each pass, with its own journal words and its own ledger namespace
- Why: the gap is precisely the ask, so the fix is precisely the ask: `factory_harness_review_sweep`
  reads the harness remote's open pulls at the end of every pass and, for each pull whose
  `/requested_reviewers` has neither `users` nor `teams`, asks the same
  `factory_review_target` through the same REST endpoint with the same throttle — while never
  ticking, dispatching, or merging against the harness, so the withheld authority full
  integration needed stays withheld and remains a separate, still-open decision. Silence was the
  original defect, so every sweep path journals — `HARNESS-POKED`, `HARNESS-POKE-ALREADY`,
  `HARNESS-POKE-FAILED`, `HARNESS-POKE-UNKNOWN`, `HARNESS-POKE-OFF`, and a
  `HARNESS-POKE-SWEEP` summary carrying `open=0` — except the no-split case, where the harness
  queue IS the queue the pass just worked and a line every pass would be the noise that hides
  the lines that matter. The throttle lives under `harness-pr:<n>` because `pr:<n>` is already a
  unit of the target queue, two repositories may share a number, and a stamp from one queue must
  not silence the other's ask. `FACTORY_HARNESS_POKE=0` turns it off and journals the refusal
  every pass: a queue that quietly stops being swept is the same silence this sweep exists to
  end. The leg measured the cost of trusting the target resolver's URL expression: its
  `s#^([^/]+[:/])?([^/]+/[^/]+)$#` matches the SSH form only — with `.git` stripped,
  `https://host/owner/name` leaves two slashes where `[^/]+/[^/]+` allows one, so the match
  answers nothing — and the live harness origin IS https (re-read 27 Nov), which would have made
  every sweep journal `HARNESS-POKE-UNKNOWN` forever; the target resolver survives https only
  through its `gh repo view` fallback, and that fallback resolves from the current directory,
  which inside a pass is the target, never the harness — so the helper carries both forms in
  `sed` itself (strip the suffix, strip a `scheme://` prefix, keep the last two path components).
- Checkpoint: 29277bc
- Effect: `factory/common.sh` gains `FACTORY_HARNESS_POKE` (default `1`) and
  `factory_harness_repo`; `factory/factory.sh` gains `factory_harness_review_sweep`, called
  before the pass disarms its death trap so its lines belong to the pass, raising `rc=4` exactly
  like the `needs_reviewer` arm; the no-split case has two silence arms — harness and root the same
  directory first (the pre-H-0407 shape every fixture pass runs: measured, the slug-only guard
  marched 18 proc legs into the strict `gh` shim and reddened them with `rc=4`), then two clones
  of one repository; `docs/factory.md` gains the sweep section beside the poke it
  completes and an env-table row; `factory/selftest.d/004-harness-queue-gets-the-ask.sh` carries
  seven claims (ask lands at the harness endpoint; dry-run only says WOULD; held is not re-asked;
  throttle per namespace with a cross-namespace control; no-split silent with no call; refused
  POST read back as ALREADY-0 versus FAILED-1; knob-off loud). Red on `origin/main` at
  leg-load ("no factory_harness_review_sweep() ... the leg would read nothing").
- Decision: H-0409
