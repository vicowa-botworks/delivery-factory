## H-0407 · With the harness in its own repository, what does "the repository" mean when the factory says it — and what may a default no longer imply?

- Question: pre-extraction, `FACTORY_ROOT` meant two things at once — *the tree the scripts
  were read from* and *the tree the factory delivers against* — one variable naming one tree,
  a claim that held only while the harness lived inside the product repository (the split's
  ancestor is `2adea1ba:factory/common.sh:1474-1476` "where the scripts were read from, and the tree the tick"). After H-0406 the naive default pointed the factory at its own
  source: a tick in the delivery-factory checkout would supervise delivery-factory, because
  that is where the timer's scripts live. Which name keeps which meaning, which default has
  to die, and what must the installed unit say so one pass knows both trees without either
  being a guess?
- Options: keep `FACTORY_ROOT` as the target, resolve the default outside the harness, refuse self-targeting that silence minted, and make the unit name both trees explicitly | rename the target to `FACTORY_TARGET` everywhere — a vocabulary change buying no new discrimination: 34 selftest legs already pass `FACTORY_ROOT=` and `FACTORY_HARNESS=` as two values, so the rename would invalidate a decade of journal, unit-file and decision vocabulary for nothing | keep the self-default and *warn* when root equals harness — a warning is the silent shape this harness keeps paying for (the 1h07m of queue silence behind `2adea1ba:factory/DECISIONS.md:3663` "so the 1h07m of queue silence the entry was written to measure would have re-timed green"), and #1180's receipts; a factory supervising its own source would read healthy
- Chose: keep `FACTORY_ROOT` as the target, resolve the default outside the harness, refuse self-targeting that silence minted, and make the unit name both trees explicitly
- Why: *watched* is a decision with a cost envelope — budgets, a reviewer team, an escalation
  label — so silence must not be able to mint it; the refusal names the knob instead of
  printing a prophecy. The guard discriminates on **git-ness, not path**: a bare non-repo
  fixture has `FACTORY_DIR/.. == FACTORY_HARNESS` by construction and keeps the old default
  byte-identically (the fixtures' premise is that the planted tree *is* the world — refusing
  or reaching for `$PWD` there would rewrite the suite's subject), while a real harness
  checkout — one with git — loses the privilege of being its own default target. An operator
  who aims the factory at this repository deliberately says so on the environment, which is
  what a decision looks like here. And the unit carries both trees as *data* because a tick
  that has to guess which repository a `repo=` field names is exactly the shape that cost
  `2adea1ba:docs/factory.md:196-197` "pointing at the old path and every timer verb read green" —
  one `ExecStart` line moved instead of two: the drift check read *installed* from the tree it
  was installed into, so a relocation read green — with `@HARNESS@` and `@REPO@` substituted from different values, one
  silently moving with the other is a visible mismatch.
