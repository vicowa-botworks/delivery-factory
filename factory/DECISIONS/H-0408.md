## H-0408 · With the `not-this-pass` refusal fired by the architecture itself, which escalation may count it — and what word may a verdict promise when the loop is forbidden the repair?

- Question: #342 armed `STALE` to name activations that reported the installed tree behind and
  did not repair it — its sentence is a promise ("the loop is reporting, not repairing") whose
  repairable half is the whole point, and #489 deliberately fed it passes aimed at a foreign
  tree because those are outages in the same shape. H-0407 then made the unit exec the harness
  checkout and supervise another repository, so `SUPERVISOR-FF-REFUSED not-this-pass` became
  true on every activation forever, and its count fed that promise. Which streak counts the
  refusal, and what does `--status` say when the thing behind is a tree H-0056 forbids this
  pass to touch?
- Options: exempt the harness tree from any streak — silence is the shape #342 was written
  against, and a harness genuinely stranded behind `origin/main` would then never escalate |
  make the gate itself conditional — skip the refusal when the harness reads `behind=0`, so the
  constant stops journalling — but H-0056's report is unconditional precisely so the refusal
  contract is witnessed every pass, and a refusal that vanishes when nothing is wrong deletes
  the only evidence the gate ran | count by tree identity: keep the refusal unconditional, and
  let the refused tree's relation to the pass decide which streak the refusal feeds, giving the
  harness tree its own ledger line and its own escalating word
- Chose: count by tree identity: keep the refusal unconditional, and let the refused tree's relation to the pass decide which streak the refusal feeds, giving the harness tree its own ledger line and its own escalating word
- Why: the escalation word is a promise about a repair, and the two repairs differ in kind:
  `STALE` says the loop could fix this and has not — a person reads it and asks why the loop is
  idle; `HARNESS-STALE` says the harness checkout the timer execs is behind and the reader is
  the repairer — pull it by hand under the claim protocol, which is the one move H-0056 left
  open. The alternative options lose loudness either way, and the live box shows the cost of
  the status quo: measured 26 Nov on the machine that runs the timer (issue #3), the streak
  read 27 and `--status` read `STALE` while the harness journal line said
  `SUPERVISOR-AT 3fafef6 dirty=0 main=3fafef6 behind=0` — an outage escalation saturated by an
  architectural constant, and a harness that *really* stalls behind would read identical to the
  constant, which retires #342's escalation by making it always true. Counting by identity
  keeps every existing contract whole: #489's foreign tree — neither the target nor the tree
  this pass can name as its harness — counts into `stale-streak` and escalates to `STALE`
  byte-for-byte; #342's blind-activation contract stands, because a position git would not
  count touches neither streak; and a pass that cannot name its own harness is foreign by the
  same reasoning #489 used — a streak may not be *cleared* on the strength of a tree identity
  the pass cannot prove. `STALE` keeps precedence where both streaks are armed: a verdict
  prints one word and the repairable failure is the one the loop can be told to fix. What
  lost: `--status` prints only the outranking word, so a box armed in both ways reads `STALE`
  until the repairable half clears, and `HARNESS-STALE` is reachable only when it is the sole
  escalation — a real harness strand hiding behind an unmerged target needs the journal, not
  the verdict line; `harness-streak` is written only when a pass runs, so a stopped timer with
  a behind harness freezes its count rather than growing it, the same staleness-of-state
  semantics `stale-streak` has always had; and two ledger lines replace one, so anything
  grepping `stale-streak` as *the* staleness fact must be re-read (nothing in this repository
  did — the greps anchor on the verdict words, which is why a new word, not a changed number,
  was the safe move).
- Checkpoint: 6a68cc7
- Effect: `factory/common.sh` gains `factory_harness_tally` and `factory_harness_reset` beside
  the stale pair, writing `supervisor.harness-streak` and `supervisor.harness-reason`; the
  #489 ownership gate in `factory_supervisor_repair` now canonicalizes `FACTORY_HARNESS`
  alongside `FACTORY_ROOT` and branches on which tree was refused — the harness tree counts its
  own streak while `behind` is a positive integer and clears it at `behind=0` (the exact live
  state #3 measured — refusal constant, tree current — now arms nothing), and the same
  `behind=0` branch clears `supervisor.stale-streak` by #342's own rule that a current tree
  clears the streak, applied to the tree the unit execs: the pre-split code reached its clear
  after the fast-forward, the post-split gate returns before it, so without that line the
  streak 28 the old counting armed on the live box would read STALE forever under the new
  code — a stuck arm is as dead an escalation as a saturated one. An uncountable
  position leaves both streaks blind, and every other tree reaches `factory_stale_tally` on the
  untouched path; the refusal line itself is byte-identical, because #3's diagnosis was that
  the count was wrong, not the sentence. `factory_verdict` gains a `HARNESS-STALE` arm ordered
  after `STALE`, its sentence naming the tree it judges and the by-hand repair it cannot make;
  the verdict-word list above the function, `factory.sh`'s `--status` usage line, the
  `docs/factory.md` refusal-and-streak paragraphs and the `FACTORY_STALE_ESCALATE` table row
  all name the sixth word. `factory/selftest.d/003-harness-behind-own-word.sh` pins the
  five-claim shape with its controls: behind-harness arms its own streak and leaves
  `stale-streak` absent while the tree provably does not move (the HEAD pair is read in the
  leg, because a repair that ff'd first would also leave a count of 1); a current harness
  clears a seeded streak of 2 to 0 while still journalling the refusal (clearing must be
  something that happens, and silence is the failure); three behind-activations escalate as
  `HARNESS-STALE` and the sentence must not carry the `STALE` promise nor omit the tree it
  names; the #489 control runs the same fixture with the harness unnameable and demands
  `stale-streak` reach 3 and the verdict read `STALE` — #3 fixed a misarm, not the escalation;
  and the precedence leg seeds both streaks past the threshold and demands `STALE`, having
  first written a fresh journal line, because `STALLED` is asked before every streak word and
  a leg that forgot that would fail on the fixture, not the code. The entry's premise is the
  H-0407 entry's own hand-off, `factory/DECISIONS/H-0407.md` at its closing lines: "`not-this-pass`
  is armed by the split itself, and it feeds the `STALE` streak — #3."
- Decision: H-0408
